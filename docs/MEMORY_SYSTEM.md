# Memory system

## Files

| Path | Purpose |
|---|---|
| `memory/raw/s1|s2/YYYY-MM-DD.md` | Redacted raw transcripts |
| `memory/notes/s1|s2/YYYY-MM-DD.md` | Daily notes written by the agent |
| `memory/MEMORY.md` | Shared long-term memory |
| `memory/STATE.md` | Mood label / energy / relationship temperature / small daily note (≤8 lines) |
| `memory/EVENTS.md` | Important dates and commitments |
| `memory/THREADS.md` | Open topics and commitments worth following up (≤10) |
| `memory/WEEKLY.md` | Weekly reflection generated by the weekly job |
| `memory/CARE_LOG.md` | Sent proactive messages, used by the weekly reflection |
| `memory/companion.sqlite3` | Sourced/versioned `current_fact` records |
| `memory/sticker_usage.json` | Sticker send history and daily quotas |
| `memory/recent_replies.md` | Last 20 assistant messages |
| `memory/CONFLICTS.md` | Contradictions waiting for a human decision |
| `memory/reminders.json` | Locally created reminder index |
| `memory/.care_plan.json` | Today's randomized care plan |

## Flow

1. **Capture** — `capture_transcripts.py` runs every 5 minutes and appends new
   messages from the cc-connect session JSON to `memory/raw/`.
2. **Assistant backfill** — `capture_review.py` appends the assistant's own
   direct replies (which the conservative capture job holds for review) to raw,
   so consolidation sees both sides of the conversation.
3. **Send logging** — `send_msg.py` appends each outgoing bubble to raw and
   recent replies.
4. **Consolidate** — the `memcons01` cron runs at 03:17, reads recent raw and
   notes, updates `MEMORY.md`, `EVENTS.md`, `STATE.md`, `THREADS.md`, and writes
   sourced facts with `companion_memory.py learn --curator`.
5. **Weekly reflection** — the weekly job writes `WEEKLY.md`, updates open
   topics/state, and reviews `CARE_LOG.md` for proactive-care quality.
6. **Recall** — `companion_memory.recall()` returns a small viewer-first packet:
   the current person's facts and shared facts come first; the other person's
   facts/statements are only included when the current message explicitly
   mentions them (or a shared "we/together" context). Relevant facts are
   filtered by score and the packet excludes the current message's own source.
7. **Search** — for older details, `memory_search.py "keyword"` returns current
   facts plus labeled legacy evidence; MEMORY.md sections are attributed to the
   right person. If nothing matches, say so instead of guessing.
8. **Regression** — `memory_eval.py` runs a small set of real retrieval cases
   during the daily consolidation and records failures without changing data.

## Redaction

`common.py` redacts common secret shapes before writing raw/recent:

- `sk-...`, GitHub/Slack tokens, bearer tokens
- password/密码/口令 fields
- API keys/tokens and private-key blocks

It is a safety net, not a guarantee. Do not send secrets to the bot, and do not
keep secrets in memory files.

## Retention

The backup script rotates launch logs after 14 days. Raw/notes/archive are kept
as memory; prune them manually according to your own privacy policy. Remember
that `memory/` and `backups/` are gitignored and must never be committed.

## Sharing between two bots

Both bots share `MEMORY.md`, `STATE.md`, and `EVENTS.md`. Daily notes are kept
per user (`s1` / `s2`) and merged during consolidation. This gives one persona
and one long-term memory while keeping the two chat channels separate.

The per-turn memory packet is viewer-first: a message from one person does not
automatically inject the other person's unrelated facts. Cross-person facts are
included only when the current message explicitly mentions the other person, or
when the message uses a shared "we/together" context. This reduces accidental
cross-user disclosure and keeps the context small. `companion_memory.py learn`
requires a real source and quote; the daily consolidation uses `--curator` so it
can write sourced facts for either person, but normal chat replies must not use
that flag.
